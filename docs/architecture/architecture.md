# Pixel Empire — Architecture

Engine: Godot 4.7.2 · GDScript · 2D (Forward+) · Design record: `design/game-brief.md`.

## 1. Guiding decisions

| # | Decision | Why |
|---|----------|-----|
| D1 | **Simulation runs in grid space, rendering in iso space.** Every entity stores `grid_pos: Vector2` (float tile coordinates). `Iso.grid_to_world()` converts for drawing only. | Pathfinding, ranges, fog, footprints and AI all reason in tiles; the projection becomes a pure presentation concern and can change (tile size, zoom) without touching gameplay. |
| D2 | **Terrain is drawn by one shader, not by thousands of tiles.** A `terrain map` texture (1 texel per tile) feeds `terrain.gdshader`, which samples tiling pixel-art textures and dithers borders between terrain types. | Organic pixel-art transitions (beach→water, grass→forest) without authoring hundreds of transition tiles; one draw call; fog of war is sampled in the same pass. |
| D3 | **All art is generated by code into PNG files** (`tools/art/generate_art.gd`, run headless) and loaded from `assets/sprites/`. | No art assets exist. Generated PNGs are ordinary files: an artist can replace any sheet without code changes as long as the frame layout in `assets/data/render_sprites.json` is respected. |
| D4 | **Gameplay numbers live in JSON** under `assets/data/` (`units_stats.json`, `resources_nodes.json`, `map_generation.json`, `camera_settings.json`, `render_sprites.json`). `GameData` (autoload) loads and validates them. | Tuning without code edits; satisfies the data-driven rule in `.claude/rules/gameplay-code.md`. |
| D5 | **Systems are plain nodes under `Game/Systems`, injected with the shared `World` context.** Entities hold state + presentation; systems hold behavior that spans entities (selection, commands, movement, fog, AI). | Avoids one monolithic game script; each system is independently testable; dependency direction is explicit. |
| D6 | **Centralised ticking.** `UnitSystem` iterates all units each physics frame (pre-allocated arrays, spatial hash for separation). Units have no `_process`. | Predictable cost for 200+ units; no per-node callback overhead; hot paths stay allocation-free. |
| D7 | **Pathfinding with `AStarGrid2D`** (8-way, no corner cutting) over the tile grid; buildings/trees/water/mountains mark cells solid. Group moves share one path search to the destination area plus formation offsets. | Built-in, C++-speed, trivially updated when trees are cut or buildings placed. |
| D8 | **Event bus for cross-system communication** (`EventBus` autoload, typed signals: `selection_changed`, `resources_changed`, `entity_died`, ...). UI never reaches into gameplay internals. | UI/gameplay decoupling rule; makes save/load and AI observers easy. |
| D9 | **Team colours are baked per player** into separate sprite sheets at generation time (`villager_p1.png`...). | Canvas shaders have no per-instance uniforms; baking keeps all sprites batchable. |

## 2. Layout

```
project.godot
src/
  core/        iso.gd (projection math), event_bus.gd*, game_data.gd*, spatial_hash.gd, rng helpers
  map/         map_data.gd (grid model), map_generator.gd, pathfinder.gd
  render/      terrain_renderer.gd, sprite_library.gd, decor_layer.gd, ground_fx.gd (move markers),
               fx_layer.gd (pixel particles + projectiles), selection_overlay.gd (health bars)
  camera/      rts_camera.gd
  gameplay/
    entities/  entity.gd (base), unit.gd, resource_node.gd, building.gd
    systems/   unit_system.gd (movement/steering + path queue), selection_system.gd, command_system.gd
               (contextual right-click), building_system.gd (placement/construction/pop cap),
               economy_system.gd (villager tasks), production_system.gd (training queues),
               combat_system.gd (targeting/damage/projectiles), fog_system.gd
    ai/        ai_player.gd (easy/normal/hard computer opponent)
    ai/        ai_player.gd (3)
  ui/          hud.gd, command_panel.gd, placement_controller.gd, minimap.gd (4)
  save/        save_system.gd (5)
  game/        main.gd, game.gd (bootstrap + wiring), players.gd
  debug/       smoke_test.gd (scripted in-game verification)
assets/
  data/        *.json gameplay/tuning data
  sprites/     generated PNG sheets (replaceable)
  shaders/     terrain.gdshader, fog
  audio/       (stage 5) placeholders + AudioBus routing
tools/art/     pixel-art generator: terrain, props, humanoids (10 anims), isometric buildings
               (3D-primitive rasteriser), scaffolds, foundations, team flags, mill sails
tests/unit/    headless unit tests (tests/run_tests.gd)
```
`*` = autoload. Autoloads are limited to stateless/registry services (`GameData`, `EventBus`); match state lives in `Game` and is passed to systems (no global game state).

## 3. Runtime scene

```
Main (game/main.gd)
└─ Game (Node2D, game/game.gd)          owns MapData, Pathfinder, players, entity registry
   ├─ World (Node2D)
   │  ├─ Terrain (terrain_renderer.gd)  shader quad, z = -100
   │  ├─ GroundFx (Node2D)              move markers, building footprints
   │  ├─ Entities (Node2D, y_sort_enabled)  units, resources, buildings
   │  └─ AirFx                          projectiles, damage text (stage 3)
   ├─ Camera (rts_camera.gd)
   ├─ Systems (Node)                    UnitSystem, SelectionSystem, CommandSystem, ...
   └─ UI (CanvasLayer)                  HUD, selection rectangle, panels
```

## 4. Coordinate conventions
- Tile size 64×32 px (diamond). `world.x = (gx - gy) * 32`, `world.y = (gx + gy) * 16`.
- `grid_pos` (0.5, 0.5) is the centre of tile (0, 0). Tile index = `floor(grid_pos)`.
- Speeds are tiles/second, ranges and sight are tiles.
- Draw order: entities are y-sorted by their world `y` (feet position = node origin).

## 5. Entity model
`Entity (Node2D)`: `id`, `owner_id` (0 = Gaia), `grid_pos`, `kind`, `def` (dictionary from GameData), `hp`, `selectable`, footprint. Visuals: `Sprite2D` sheet with `hframes/vframes`; frame chosen by `(animation, direction, time)` via `SpriteLibrary` animation tables. Shadows and selection ellipses are drawn by the entity's `_draw()`.

`Unit` adds: path, speed, facing (8 directions, 5 drawn + horizontal flip), state machine.

Unit state table (stage 1; extended in later stages):

| State | Enter when | Leaves to |
|-------|-----------|-----------|
| IDLE | spawned, arrived, path failed | MOVING on move order |
| MOVING | move order with a valid path | IDLE on arrival / path failure |

Economic work is a second layer on top of locomotion (`Unit.task`, driven by `EconomySystem`):

| Task | Phases |
|------|--------|
| gather | to_node → work (fills `carry_capacity`) → to_drop (nearest accepting drop site) → to_node; replacement node within `search_radius` when depleted |
| build | to_site → work (adds to `Building.builders_this_tick`) → auto-gather if the building is a drop site |
| repair | to_site → work (pays `repair_cost_fraction` of cost per full HP) |
| drop | to_site → deposit |

`Building` states: FOUNDATION → CONSTRUCTING → COMPLETE. Construction speed with n builders = (n+2)/3 (AoE rule).
Training (`ProductionSystem`): cost paid on enqueue, refunded on cancel, front item waits while population ≥ cap.
Combat (`CombatSystem`) is a third layer on units: `target`, `guard_pos`, `attack_move_goal`, `stance`.
Idle military units (and attack-moving ones) scan visible enemies every `scan_interval`; out of range they
chase (repath 0.5 s), in range they swing (melee damage lands `melee_hit_delay` later; ranged spawn arrows/rocks).
Auto-engaged units are leashed to `guard_pos` and walk back after the fight. Damage =
max(1, attack − armor[melee|pierce]) + class bonuses. Death: `Entity.killed` → corpse (die animation, fades) or
rubble for buildings. Defensive buildings (`attack` block) fire arrows.

Fog of war (`FogSystem`): per-player visible/explored byte grids rebuilt at 8 Hz from unit/building sight;
the local grid drives `fog.gdshader` (dithered, jittered edges) and hides enemy units. Every system that picks
targets asks `fog.is_visible(player, entity)`, so the AI is bound by the same fog.

AI (`gameplay/ai/ai_player.gd`): a node per computer player that only issues orders through the public systems
(economy, buildings, production, commands, combat) — no hidden state changes besides the difficulty's gather
multiplier. Think loop: economy (deficit assignment + rebalancing) → build → train → age up → scout → defend → attack.

## 6. Performance budget
60 fps with 200 units on a 128×128 map. Measures: single terrain draw call; atlas-shared sprites batch; `UnitSystem` uses a spatial hash rebuilt per frame into pre-allocated buckets; pathfinding requests are rate-limited per frame (queue) once AI arrives; fog texture updated at 8 Hz.

## 7. Testing
- `tests/run_tests.gd` (headless SceneTree): iso round-trip, generator determinism and connectivity, pathfinder, data validation.
- `src/debug/smoke_test.gd`: launched with `-- --smoke`; drives real input events (box select, right-click move, gathering, placement, training), asserts outcomes, writes screenshots to `production/qa/screenshots/`, exits with code 0/1.
- `src/debug/smoke_combat.gd`: `-- --smoke=combat --mode=skirmish` (scripted fights, projectiles, siege, towers, fog, age-up) and `-- --smoke=ai --mode=skirmish --difficulty=hard` (accelerated AI match: economy, buildings, army, scouting, attack).
- `run_tests.bat` runs everything. Matches are reproducible: global RNG and AI RNG are seeded from the map seed.
